# JASS FlightFinder Studio — V0.2 Architecture

## Goal

Separate the user interface from flight providers and make itinerary scoring deterministic and explainable.

## Core pipeline

1. User enters search criteria.
2. Provider adapter receives normalized criteria.
3. Provider returns normalized offers.
4. JASS Value Engine scores each offer.
5. UI presents Cheapest, Fastest and Best Value.
6. Future fare-watch service can persist selected offers.

## Why provider abstraction?

Flight APIs have different schemas, credentials, commercial rules and booking flows. The UI should never depend on one provider's response format.

## V0.2 score factors

- 35% price
- 25% duration
- stops
- baggage
- emissions

The weighting is deliberately visible in code and can later become configurable in Settings.
